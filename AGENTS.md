# AGENTS.md — guidance for AI agents working in this repo

This is a **Nix home-manager** dotfiles repository (flake-based, standalone
home-manager). The Nix configuration is the **single source of truth** for the
user's environment.

## Golden rule

Change configuration by editing the **Nix source** under `home-manager/`, then
applying it — **not** by editing the live/generated files in `~/.config/`.

Many files under `~/.config/` are either:

- **Read-only symlinks into `/nix/store`** — e.g. `~/.config/nvim` →
  `/nix/store/…-home-manager-files/.config/nvim`. You cannot edit these in place.
- **Generated by home-manager modules** (`programs.*` in `home.nix`, e.g. git,
  zsh, kitty). Edits to the live files are overwritten on the next rebuild.

## Where things live

- `home-manager/home.nix` — main config: `home.packages`, `programs.*` modules
  (git, zsh, kitty, …), services, shell aliases.
- `home-manager/flake.nix` — flake inputs (nixpkgs `nixos-unstable`,
  home-manager). Output: `homeConfigurations."larsski"`.
- `home-manager/nvim/` — Neovim config source; linked via
  `xdg.configFile."nvim".source = ./nvim` in `home.nix`. Edit files here, not
  `~/.config/nvim`.
- `home-manager/claude.nix` — Claude Code config (imported by `home.nix`): the
  `claude-code` package, `~/.claude/settings.json` (generated from Nix), the
  statusline, and per-skill symlinks.
- `home-manager/claude/statusline.sh` — the Claude statusline script; runs from
  the Nix store. Edit here.
- `home-manager/claude/skills/<name>/` — Claude skills; each dir is auto-linked
  into `~/.claude/skills/`. Drop a new dir here to add a skill.

## How to make common changes

- **Install a package** → add it to `home.packages` in `home.nix`. Do not use
  `nix-env -i`, `apt`, `npm -g`, `pip install`, etc.
- **Change a program's settings** (git, zsh, kitty, …) → edit the matching
  `programs.<name>` block in `home.nix`.
- **Change Neovim** → edit files under `home-manager/nvim/`.
- **Add a shell alias** → `programs.zsh.shellAliases` in `home.nix`.

## Apply changes

```sh
home-manager switch --flake ~/.config/home-manager#larsski
```

## Claude Code (Nix-managed)

Claude Code is managed by Nix via `home-manager/claude.nix`:

- **Package** — `pkgs.claude-code`, pinned to nixpkgs. It does **not**
  self-update; update with `nix flake update` + `home-manager switch`. The native
  installer (`~/.local/{bin,share}/claude`) has been removed.
- **`~/.claude/settings.json`** — generated from `claude.nix` as a **read-only**
  Nix store symlink. Change model / effortLevel / theme / enabledPlugins /
  statusline by editing `claude.nix` + `home-manager switch`, **not** via
  Claude's `/config`, `/model`, or `/statusline` (those runtime writes fail
  against the read-only file).
- **Statusline** — `home-manager/claude/statusline.sh`.
- **Skills** — `home-manager/claude/skills/<name>/`, auto-linked into
  `~/.claude/skills/`.

## Exceptions — mutable runtime state (leave outside Nix)

Do **not** try to Nix-manage these; they are runtime state Claude writes itself:

- `~/.claude.json`, credentials, history, sessions, todos, caches, projects.
- Plugins: only the *enable flag* lives in Nix (`enabledPlugins` in
  `claude.nix`). The plugin code, marketplaces, the claude-mem daemon, and its
  memory database are installed and managed by Claude at runtime — on a fresh
  machine the plugin must be installed manually once.

## Git

`.gitignore` ignores `*` and then re-includes specific paths with `!`. When you
add a new file that should be tracked, add a matching `!path` whitelist entry.
